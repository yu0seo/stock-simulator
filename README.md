# 대가 · DAEGA

과거 1년의 주식시장을 12개 스테이지로 경험하는 투자 학습 웹 앱입니다. React + TypeScript + Vite, Python FastAPI, Supabase Auth/PostgreSQL, FinanceDataReader 과거 주가, OpenDART 공시를 사용합니다. 토스증권 연동과 실시간 시세·주문은 사용하지 않습니다.

## 현재 게임 규칙

- 2024년 1월 1일~12월 31일, 국내 50개 종목. 초기자금 1,000만 원으로 시작합니다.
- 한 달이 정확히 30분입니다. 달력상 날짜 수에 비례해 시간이 흐르므로 31일인 달과 29일인 달의 하루 길이가 다릅니다. 윤년을 처리합니다.
- 매일 해당 날짜의 종가를 그날의 가격으로 사용합니다. 장중 가격은 만들지 않습니다. 휴장일은 직전 거래일 가격을 유지하고 일반 매매는 제한합니다.
- 1·4·7·10월 시작 전에는 시간이 멈춘 상태에서 재무제표를 비교하고 관심 종목·전략 노트를 저장할 수 있습니다. 플레이어가 시작 버튼을 눌러야 진행합니다.
- 상환금은 1월 50만 원에서 매달 10만 원씩 증가해 12월 160만 원, 총 1,260만 원입니다. 기존 난이도별 추가 대출·연이자는 사용하지 않습니다. 초기자금은 빌린 투자자금으로 제공하며, 전체 상환 일정이 게임의 의무입니다.
- 월말에는 날짜를 멈추고 **매도와 정해진 금액의 상환만** 허용합니다. 현금이 부족해도 보유 주식으로 마련할 수 있으면 바로 실패하지 않습니다. 월말 직전 거래 가능 가격으로 정산 매도하는 게임 규칙이며 휴장일에도 가능합니다. 당시 거래정지 상태인 종목은 정산 매도할 수 없습니다.
- 현금과 매도 가능한 주식을 합쳐도 상환금이 부족하면 실패합니다. 납부하면 다음 달 준비 화면으로 이동하며, 다음 달은 직접 시작해야 합니다. 12월 마지막 납부 후 완주합니다.
- 수수료·세금·배당·호가·거래량에 따른 체결 제한·공매도는 반영하지 않습니다. 원 단위 주식 수량만 허용합니다. 공급자의 과거 가격 조정 방식을 따르며 별도의 기업행동 현금흐름은 처리하지 않습니다. 정확한 계좌 복원이 아닌 일별 가격 기반 학습 시뮬레이션입니다.
- 현재 자산 = 현금 + 주식 평가액. 투자손익 = 현재 자산 + 누적 상환금 − 초기자금. 상환 자체를 투자손실로 계산하지 않습니다. 수익률은 투자손익 ÷ 초기자금입니다.
- 퀴즈는 완료 이력만 기록하고 현금을 지급하지 않습니다. 랭킹은 같은 연도·규칙·데이터 버전끼리 통과 스테이지 수, 남은 자산 순으로 비교합니다. 현재 여정의 마지막 저장 상태를 비교하며 이전 보관 기록은 합산하지 않습니다.

## 실행

Python 3.11 이상, Node.js 20.19 이상과 pnpm이 필요합니다. 현재 작업 PC에는 `.venv`, `node_modules`를 준비했습니다.

```powershell
# 최초 설치
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-data.txt
pnpm install
# .env가 없을 때만 복사하세요. 기존 인증키를 덮어쓰지 마세요.
Copy-Item .env.example .env
```

`.env`에 Supabase와 OpenDART 설정을 넣은 뒤, 먼저 데이터 파일을 준비합니다.

```powershell
.\.venv\Scripts\python.exe scripts/prepare_history.py --year 2024
```

빌드 후 한 개의 서버로 실행:

```powershell
pnpm run build
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

브라우저: http://localhost:8000 / API 문서: http://localhost:8000/docs

개발 중에는 백엔드와 `pnpm run dev`를 각각 실행하고 http://localhost:5173 에 접속합니다. 프론트엔드 소스를 수정하면 `pnpm run build`를 다시 실행해야 단일 서버 화면에 반영됩니다.

## 수정할 설정

저장소 루트 `.env`에서 설정하고 서버를 재시작합니다.

```dotenv
GAME_YEAR=2024
INITIAL_CAPITAL=10000000
STAGE_MINUTES=30
ENABLE_DEBUG_TOOLS=false
STAGE_PAYMENTS=[500000,600000,700000,800000,900000,1000000,1100000,1200000,1300000,1400000,1500000,1600000]
```

`STAGE_PAYMENTS`는 1~12월 상환금 12개를 담은 JSON 배열이며 금액 단위는 원입니다. 달마다 자유롭게 바꿀 수 있습니다. `STAGE_MINUTES`는 화면 확인용으로 짧게 설정할 수도 있습니다. 설정은 **새 여정을 만들 때 저장**하므로, 이미 진행 중인 게임은 기존 규칙을 유지합니다. 설정이 달라진 기록은 같은 랭킹에 포함하지 않습니다. 다른 연도를 선택하려면 해당 연도의 데이터도 준비해야 합니다.

`TOSS_*`, `KIS_*`, `DATA_MODE`, `GAME_DAYS`, `DART_BUSINESS_YEAR`는 새 게임에서 사용하지 않습니다. 기존 `.env`에 남아 있어도 무시합니다. 서버 전용 키를 `VITE_*` 변수에 넣지 마세요.

## 과거 데이터 준비·검증

`scripts/prepare_history.py`는 FinanceDataReader의 `NAVER:` 제공처를 명시해서 일별 OHLCV를 가져옵니다. 시작 전 차트와 1월 초 휴장일 가격을 위해 이전 연도 9월부터 수집합니다. 데이터는 Git에서 제외된 `backend/data/historical/2024/`에 저장됩니다.

```text
2024/
  005930.csv … 068270.csv   # Date,Open,High,Low,Close,Volume
  calendar.json            # 선택한 50개 종목에서 거래량이 존재한 날짜의 합집합
  financials.json          # 공시일·기준기간·접수번호가 포함된 OpenDART 원본 항목
  manifest.json            # 출처·수집시각·각 파일 SHA-256
```

달력은 선택한 50개 종목의 거래일을 대조해 만드는 방식입니다. 거래소의 독립적인 공식 휴장일 API는 사용하지 않습니다. 특정 종목에서 값이 없거나 거래량이 0이면 그 종목의 일반 매매를 막습니다. 데이터 파일은 서버 메모리에 캐시하며, 파일을 교체하면 서버를 재시작해야 합니다.

중복·누락·가격·거래량·파일 해시를 확인합니다. 데이터가 없거나 검증에 실패하면 거래를 막고 준비 안내를 표시하며, 임의 가격으로 대체하지 않습니다. 진행 중 게임은 데이터 해시를 저장하므로 다른 스냅샷으로 몰래 바뀌지 않습니다. 원본 스냅샷을 보관하세요. 기존 가격을 유지하는 `--expand` 확장은 아래 호환 절차를 따릅니다. 가격을 재수집해 바뀐 일반 스냅샷은 이전 파일을 복원하거나 새 여정을 시작해야 합니다.

OpenDART 키 없이 **주가만** 확인하려면 명시적으로 다음을 사용합니다. 이 경우 재무제표 미준비 안내가 표시됩니다.

```powershell
.\.venv\Scripts\python.exe scripts/prepare_history.py --year 2024 --prices-only
```

## 공시일 기준 재무제표

`.env`의 `OPENDART_API_KEY`를 사용해 데이터 준비 시 공시를 미리 저장합니다. 게임 도중에는 외부 재무 API를 호출하지 않습니다.

- 시작 전 공개된 자료를 위해 이전 연도 분기·반기·연간 보고서를 함께 준비합니다. 2024년 1월에는 2023년 공개 자료를 보고 전략을 세우며, 2024년 실적이 미리 노출되지 않습니다.
- 공시검색의 **실제 접수일**이 게임 날짜 이하인 자료만 표시합니다. 해당 분기가 끝났다는 이유만으로 보고서를 공개하지 않습니다. 일별 시뮬레이션이므로 공시 시각은 세분화하지 않고 공개일에 사용할 수 있습니다.
- 재무제표 응답의 모든 접수번호와 공시검색 번호를 일치시킵니다. 나중에 정정된 값을 과거 최초 공시일로 소급하지 않습니다. API가 나중 정정본만 제공해 당시 자료를 검증할 수 없으면 미제공 처리하며, 원본 공시 링크로 확인할 수 있습니다.
- 연결 우선, 연결 자료가 없을 때 별도를 사용합니다. 분·반기 당기 손익은 3개월 값, 누적 손익은 원본 전체 항목에서 별도 표시합니다.
- 이전 실시간 버전의 현재 주식 수·연간 EPS 기반 PER/PBR은 사용하지 않습니다. 주식분할과 과거 주당 수치의 기준 일치를 검증하지 못한 비율을 추정하지 않습니다. 재무제표와 공시 원문으로 비교 학습합니다.
- 차트·시세·공시 API는 서버의 플레이어별 날짜를 사용합니다. 브라우저에 연간 전체 미래 가격 파일을 전달하지 않습니다.

출처: [FinanceDataReader](https://github.com/FinanceData/FinanceDataReader), [OpenDART 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020), [공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001).

## 저장과 일시정지

4초마다 서버에서 진행을 계산하고 저장합니다. 일시정지 버튼·탭 숨김·페이지 종료 시 정지를 요청합니다. 네트워크 단절이나 강제 종료로 요청이 도착하지 않아도, 마지막 연결 이후 12초를 넘기면 그 공백을 진행 시간에 더하지 않고 정지합니다. 서버 재시작도 감지합니다. 강제 종료 시 마지막 저장 이후의 짧은 구간은 소실될 수 있습니다. 시간과 체결 가격은 브라우저가 제출하지 않고 서버에서 결정합니다. 다시 들어오면 직접 이어하기를 눌러 진행합니다.

Supabase는 기존 SQL `supabase/migrations/202610280001_daega.sql`의 `profiles`, `accounts`, `save_account` 함수를 그대로 사용합니다. 이미 테이블을 만들었다면 새 SQL을 실행할 필요가 없습니다. 신규 프로젝트는 SQL Editor에서 해당 마이그레이션을 실행하고 `.env`에 `SUPABASE_URL`, 기존 JWT 형식 `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 설정하세요. 이메일 인증은 Supabase Auth 설정을 따릅니다.

`accounts.data`의 새 저장 형식:

```json
{
  "schema": 2,
  "campaign": {"stage": 1, "phase": "strategy", "rules": {}, "positions": {}, "trades": [], "payments": [], "strategies": {}, "completed": []},
  "archives": []
}
```

실제 객체에는 현금, 날짜 계산에 필요한 경과시간, 규칙과 데이터 버전 등이 함께 저장됩니다. 새 게임을 만들 때 이전 실시간 JSON은 `archives`에 원형 보존하며, 재시작한 여정도 추가 보관합니다. **이전 기록 보관함**에서 자기 기록을 JSON으로 내려받을 수 있습니다. 예전 기록의 종목을 새 게임 가격으로 재평가하지 않습니다. 저장은 기존 버전 비교 방식으로 동시 요청의 덮어쓰기를 방지합니다.

Supabase 설정이 없는 경우만 로컬 SQLite `backend/data/daega.sqlite3`를 사용합니다. `AUTH_MODE=local`로 명시할 수도 있습니다. 클라우드 저장 오류 시 로컬 저장으로 전환하지 않습니다. `.env`, DB, 다운로드 데이터, 테스트 산출물은 Git에 올라가지 않습니다. Git으로 받은 다른 PC에서는 설치와 데이터 준비를 다시 실행하세요.

## 유사 기업 추천과 50종목 확장

종목·재무 탐색 화면의 하위 탭 **유사 기업 추천**에서 기준 기업을 고르면 재무 군집 지도와 가까운 기업 6곳을 볼 수 있습니다. 점 선택·기준 기업 선택·군집 필터·공시 출처 확인을 지원합니다.

게임 날짜까지 공개된 최신 검증 재무제표의 총자산 규모, 부채/자산, 연환산 순이익/기말자산을 비교합니다. 규모는 로그 변환하고 이익률은 asinh 변환한 뒤 각 지표를 표준화합니다. 원래 3차원 지표에서 결정적인 초기값으로 K-means 최대 5개 군집을 구하고, PCA의 상위 2개 축으로 그립니다. 추천 순서는 원래 3차원 지표의 유클리드 거리입니다. 2차원 그림의 간격과 실제 추천 순서는 일부 다를 수 있습니다. 연환산 이익/기말자산은 평균자산 기준 ROA나 미래 이익 예측이 아닙니다.

50개 기업 모두를 검사하지만, 그 날짜까지 검증 가능한 공시가 없거나 필요한 지표가 모호하면 **현재 비교 자료가 부족한 기업**으로 따로 표시합니다. 미래 보고서나 임의 값으로 군집을 채우지 않습니다. 각 기업의 실적 기간과 공개일, 연결·별도 기준, 사용 공시 원문을 확인할 수 있습니다.

기존 8종목 파일을 유지하며 50종목으로 확장하려면:

```powershell
.\.venv\Scripts\python.exe scripts/prepare_history.py --year 2024 --expand
```

이 옵션은 기존 파일의 해시를 검증하고, 기존 가격·공시를 다시 내려받거나 바꾸지 않고 새로운 종목을 추가합니다. 기존 스냅샷은 `snapshots/<기존 데이터 ID>/`에 보관합니다. 새 종목의 공시 고유번호는 OpenDART 공식 고유번호 디렉터리에서 가져옵니다. 호환 가능한 이전 스냅샷 ID를 기록하므로, 서버 재시작 후 기존 게임을 불러오면 현금·보유 수량·거래·상환 기록을 그대로 유지하며 새 데이터 ID를 적용합니다. 업그레이드 이력도 계정 안에 남습니다. 임의로 가격 파일을 바꾼 다른 스냅샷은 계속 거부합니다.

## 일시정지와 분석 접근 제한

일시정지하면 전체 화면을 잠그고 이어하기 버튼만 제공합니다. 열려 있던 종목·재무 창도 닫습니다. 기업 분석과 차트, 군집, 학습·랭킹·기록 등의 API도 일시정지 계정에서 직접 호출하면 거부합니다. 여러 브라우저 탭이 같은 계정을 사용해도 서버에 저장된 상태를 기준으로 제한합니다. 다시 접속하거나 새로고침해도 잠금은 유지합니다.

다음 달 준비와 월말 정산 중에도 기업 분석은 열리지 않습니다. 월말에는 보유 종목의 매도와 상환을 허용합니다. 새 분기의 전략 수립 단계와 실제 시간이 흐르는 진행 중에 기업 분석을 이용할 수 있습니다.

## 스테이지 디버깅

현재 작업 PC의 `.env`에는 `ENABLE_DEBUG_TOOLS=true`를 설정했습니다. 다른 환경의 기본값과 `.env.example`은 `false`입니다. 설정을 바꾼 뒤 서버를 재시작하세요.

게임을 시작하면 투자 여정 화면에 다음 버튼이 나타납니다.

- **이번 스테이지 마지막 날로 이동**: 해당 월의 실제 마지막 날짜로 이동하고 진행을 계속합니다. 그날 가격으로 보유 주식 평가와 매매를 확인할 수 있습니다. 30분 스테이지라면 마지막 하루에 해당하는 약 1분이 남습니다.
- **월말 정산으로 이동**: 해당 월의 시간을 끝내고 매도·상환 화면으로 이동합니다. 정상 상환 규칙을 그대로 적용하며 현금이나 주식을 지급하지 않습니다. 다음 달은 상환 후 직접 시작합니다.

윤년의 2월 29일과 30·31일인 달을 구분합니다. 이미 지난 날로 되돌아가지 않으며 분기 전략 수립을 자동으로 건너뛰지 않습니다. 디버깅을 한 번이라도 사용하면 해당 여정은 `debug_used` 및 `debug_events`에 기록되고 일반 랭킹에서 제외됩니다. 새 여정을 만들면 별도 정상 기록으로 시작합니다. API는 로그인과 디버깅 설정을 모두 확인합니다.
